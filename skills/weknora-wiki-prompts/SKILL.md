# WeKnora Wiki 提示词生成

WeKnora 知识库的 Wiki 功能接收两段**业务指令**，系统把它们追加在自有提示词之后，且系统自有规则永远优先。本技能的产出就是这两段指令，核心原则一句话：**只写领域侧重，不重述系统协议**。若用户带来的是已有提示词但效果不满意，先按步骤 1 建领域清单，再对照反馈定位：页面表达偏泛 → 改内容生成要求；实体碎片化或漏提取 → 改提取重点；其余流程相同。

## 两段指令与注入点

| 指令 | 配置字段 | 注入点 | 控制什么 |
|---|---|---|---|
| Wiki 提取重点 | `ExtractionInstructions` | 实体/概念抽取调用 | 在这份语料里识别哪些实体、哪些概念、如何取舍 |
| Wiki 内容生成要求 | `ContentInstructions` | 文档摘要页、实体/概念页面、首页索引简介，共三处 | 摘要、页面、首页各自的表达重点 |

抽取管线是写提取重点时的心智模型：LLM 从文档抽出 `entities` / `concepts` 两个 JSON 数组，字段固定为 `name`、`slug`（`entity/…`、`concept/…`）、`aliases`、`description`（索引展示用的一句话）、`details`；另一个 pass 把实质讨论该条目的 chunk id（`source_chunks`）挂到每个 slug 上。这些全部由系统协议拥有。

**硬边界（两段通用）**：单段 ≤ 4000 字符（按字符计，`len(文本)`）；结尾保留一句兼容声明「与系统协议冲突时以系统协议为准」。系统自有、一律不重述的内容：JSON 结构与字段语义、slug 生成与沿用规则、chunk 引用协议、摘要首行 SUMMARY 格式、`[[slug|名称]]` 链接语法、图片 URL 原样保留、首页简介篇幅限制。

## 流程

### 1. 通读语料，建立领域清单

先读导览类文档（阅读导览、README、目录），再抽读 2–3 份核心分册的首页与代表性章节；PDF 语料用 `python3` + `pdfplumber` 抽文本（环境常无 pdftotext）。

产出四样东西，每条都能指回来源文件，缺一不可：

- 模块 / 产品 / 分册清单
- 实体候选（具名事物：系统、模块、类、接口、配置键、协议、外部依赖）
- 概念候选（机制、方法、主题）
- 别名映射与版本事实（版本号、依赖及版本、版本变更点）

完成标准：清单中每一行都能指回具体来源文件，且实体/概念候选都带具体名称而非泛类别。

### 2. 起草「Wiki 提取重点」

结构固定：开头一段兼容声明 → 一、应重点识别的实体（按 系统级 / 模块级 / 代码级 / 协议与依赖 分层列举，给具体名字）→ 二、应重点识别的概念（穷举机制与主题）→ 三、取舍与粒度规则。

粒度规则是防碎片化的关键，必须包含：实质讨论的提取标准（出现频次或专门章节/配置/示例）；提取优先级排序；aliases 只收同一事物的别名；实体归具名事物、概念归机制方法的归类判据；跳过项（版权页、页眉页脚、目录、元信息、参数值本身）；哪些内容只进页面、不建独立条目（如枚举值、单个配置项默认值）。

### 3. 起草「Wiki 内容生成要求」

结构固定：语料定位段（语料是什么、面向谁）→ 一、摘要（结构模板 + 必须原样保留的代码级事实 + 框架能力与外部依赖的归属区分）→ 二、实体与概念页面（页面开头回答什么、正文组织顺序、配置类内容的表达要求、多取值主题用表格、版本边界、页面间互引）→ 三、首页（在系统限制的简短篇幅内优先点明的 2–4 件事：语料定位、能力全景、典型场景、版本主线）→ 四、通用要求（语言与缩写、忠于原文、跳过非正文、兼容声明）。

### 4. 校验与交付

逐段校验：两段各 ≤ 4000 字符；领域事实全部来自语料原文；未复述系统协议；两段结尾都有兼容声明。

在语料目录下写两个文件：`Wiki提示词-内容生成要求.md`、`Wiki提示词-提取重点.md`，并在聊天中给出全文与字符数。

完成标准：两个文件已写入、字符数已报告且均 ≤ 4000、用户可直接粘贴进 WeKnora 知识库设置。

## 质量标准

- **具体性**：清单给具体名称（「意图引擎」而非「功能模块」；类名、配置键写全）。出现泛类别条目即视为未完成。
- **深度校准**：目标 1500–2500 字符/段——覆盖领域但不臃肿；逼近 4000 上限不加分。
- **配对一致**：内容生成要求里强调的模块与术语，必须与提取重点的清单同源。
- **样例校准**：动笔前读 [references/example-agent-framework.md](references/example-agent-framework.md)——由真实语料《智能体应用开发框架》4.0.1.RELEASE（17 份 PDF）生成的成对样例，用于校准口吻、结构与颗粒度。
