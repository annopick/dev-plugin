1. 首句点明该文档对应的框架模块、文档定位（功能介绍 / 开发指南 / 配置参考）与版本 4.0.1.RELEASE。

3. 必须原样保留代码级事实：配置键（yaml 键名）、类 / 接口 / 方法名、枚举值、默认值、依赖与版本（如 ccb-framework 3.0.0.release、SpringBoot 3.5.11、JDK 17）、接口路径与报文字段名；不得改写、意译或省略。

二、实体与概念页面
1. 页面开头段落回答"这是什么、在框架中处于什么位置、解决什么问题"；在忠实原文的前提下，正文优先按"能力与特性 → 配置方式（配置项与示例）→ 开发 / 调用方式（代码、接口、demo）→ 注意事项与约束"组织。

4. 标明版本边界：能力自哪个版本引入、4.0.1.RELEASE 的变更点（链路跟踪 OpenTelemetry 适配、A2A 协议、多模态文档与音频解析、行内统一 RAG 接入）。
5. 相关模块间自然相互引用（如 意图引擎↔Skill、单 / 多智能体↔MCP 工具、自定义扩展↔安全拦截），帮助读者沿调用链导航。

三、首页（索引页简介）

四、通用语言与忠实性要求
1. 中文书写；专有名词与缩写（MCP、RAG、A2A、AG-UI、STM / LTM、MNG、Skill、Hook）首次出现保留英文原形，全篇叫法统一。
2. 忠于原文：不推断、不补充文档中不存在的配置、参数、接口或版本号；不同文档信息冲突时如实分别呈现并注明来源差异。
3. 跳过版权与保密声明、水印、页眉页脚、目录等非正文内容。
4. 本指令仅为内容侧重指引；系统规定的输出格式、页面结构、页面链接与引用协议始终优先，本指令不与之冲突。

## 样例二：Wiki 提取重点（ExtractionInstructions）

2. 框架功能模块（有独立分册或独立配置体系者）：请求接入（多模态）、意图引擎、执行引擎、单智能体、多智能体编排、记忆管理、技能 Skill、MCP 服务及工具、AG-UI 接入、自定义扩展（Hook 与拦截器）、知识库检索、链路跟踪、A2A 通信。
3. 代码级构件：被实质讨论的类、接口、策略与注册结构（如 AgentRegistration、AgentPool、AgentExecutionStrategy、ProcessRequest / ProcessContext、WorkflowToolRegistry、DirectAgent、LoopAgentStrategy、GraphStrategy、RoutingStrategy、SupervisorStrategy、sensitiveDataInterceptor），以及被整节专门讲解的配置键（如 context-source、ltm-write-mode、patternType、ccbMcpClients、toolExecutionConfig）。
4. 协议、技术与外部依赖：MCP、A2A、JSONRPC 2.0 + SSE、AG-UI、OpenTelemetry、RAG、SpringBoot、JDK、Maven。
5. 编排模式枚举值（SINGLE/SEQUENTIAL/PARALLEL/LOOP/GRAPH/ROUTING/SUPERVISOR/MSGHUB/DEBATE）一般在所属模块或概念页内说明，不逐个提为实体，除非文档用专门篇幅单独讲解。

三、取舍与粒度规则
1. 以"实质讨论"为准：出现两次以上，或有专门章节、配置、代码示例、流程说明的才提取；仅在目录、导览、版本变更表格中一笔带过的不提取。

3. aliases 只收指同一事物的中英文名、缩写与全简称（如 OneAgent、MCP、RAG、AG-UI、STM / LTM、MNG），不收上位类别、下位功能或相关词。
4. 实体与概念不重复归类：具名组件、系统、类、协议归 entities；机制、方法、主题归 concepts。功能模块（如"记忆管理"）归实体，其背后的机制原理（如"长期记忆写入策略"）归概念。
5. 跳过：版权与保密声明、页眉页脚、目录、阅读导览类元信息；版本号、参数取值、阈值等数值本身不作为实体。
6. 实体与概念的名称、描述统一使用中文，缩写保留英文原形。
7. description 用于索引列表展示，请自含地概括该实体 / 概念在框架中的角色，例如"MCP 服务及工具——框架的标准化工具扩展模块，负责 MCP 注册发现与 function calling 工具调用"。
